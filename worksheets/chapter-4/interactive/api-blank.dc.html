API

One project can have multiple APIs, so it is helpful to keep the logic in the service layer. For this worksheet, pick one API type to get practice with it. Below is the same Contractor Profile example written three ways so you can compare, then choose. Aim to return data the client can display as-is, so the same call works across web and mobile. Then stay flexible. Once it is live, see how people are using it, and tune the endpoints toward what they reach for most.

One example, three API types

The Contractor Profile page needs to create a profile and fetch a profile. Here is that same functionality in each style.

RESTsimple, default for web & mobile
POST /api/contractors          create a contractor profile
GET  /api/contractors/{id}     fetch a contractor profile
GraphQLone call, client picks fields
query    { contractor(id: ID!): Contractor }
mutation { createContractor(input: CreateContractorInput!): Contractor }
gRPCfast, internal service-to-service
service ContractorService {
  rpc CreateContractorProfile (ContractorProfileRequest) returns (ContractorProfileResponse);
  rpc GetContractorProfile (GetContractorProfileRequest) returns (ContractorProfileResponse);
}
