Alert Audit

This worksheet will provide a framework to systematically improve your alerts. You should aim for a smaller set of alerts that are actionable and tied to user impact. If you would not be comfortable with an alert triggering a page to a coworker in the middle of the night, it should not survive the audit. Try to schedule this audit at least once per year. This is a great task for someone during a quiet on-call or a new engineer you want to better understand the system.

User Impact

For each alert, decide whether a user notices anything when it fires. If yes, describe what they experience, such as a failed checkout, a slow page, or missing data. If no, the alert is watching an internal system state, and you should question whether it needs to page anyone.

03

Alert Response

If the on-call engineer cannot figure out how to respond to the alert, it is not useful. Runbooks are the classic answer to this problem. Now we can also ask AI to review the code, data, and logs to help us debug. The question then is not whether documentation exists, but whether an on-call engineer can respond in a reasonable amount of time.
