Frontend Decision Worksheet

Renovation Revolution

Now you are the Senior Frontend Engineer. It can be helpful to map how each persona moves through the app before writing any code. Then you can make the technical decisions that shape the whole project. Many times these are carried over from previous projects, but it is helpful to have a checklist to ensure completeness.

01

User Workflow

For each persona, note the devices they use, tell the story of their trip through the app in plain words, then write that same trip as shorthand page flows (page → page). The Contractor persona is filled in as an example, and the Homeowner is left blank for you to fill in. This is another way of visualizing the navigation. There is no one right answer, so use your knowledge of the user stories and the example to fill in the Homeowner persona.

Devices
As the Contractor, I am often on the road and tend to use iPhone devices to interact with applications. I am rarely able to work on a desktop.
Page Flow Story
As the contractor, I will first start with the onboarding user workflow. Then I will review the information I have provided that is visible to others on my profile page. When I am satisfied with my profile, I can start reviewing the available projects on the summary page. From there, I will select a project and can view a limited set of project information, excluding any homeowner contact information. If it looks interesting to me, I will create a bid for that contract. Once a project is awarded, I can view homeowner contact information. I can examine each room in the project in detail and suggest changes to the work or purchases, and the project details page shows the status of any suggestions I have made.

02

Project Decisions

Each decision comes with a definition and a few options to weigh. Think about what you would use for Renovation Revolution. The most common choice as of 2026 is already selected (shown filled in), but pick or write what is best for your team.

◇ AI Prompt
"You are a senior frontend engineer helping me choose the architecture for [project description]. [number of engineers, time to MVP]. For each decision I name (I will paste the list), give me two or three realistic options. For each option, list the pros, the cons, and the team size or timeline it suits. Then recommend one option for this project in a sentence and name the biggest risk of picking it. Keep each decision to a short table."
03

Page Decisions

With the project decisions settled, you can work through each page. This worksheet lists every page decision that needs to be made. You don't have to write it all out for each page, but it is worth doing once to get in the flow of making these decisions. I have included an example for each one based on the case study.
