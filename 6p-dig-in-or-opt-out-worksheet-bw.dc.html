Dig In or Opt Out

How to choose what to learn

Pick one new software engineering tool, method, or library you have heard about. Work it through the questions below and decide whether it earns your time.

01

Source

Where did you hear about it? It could have been several places, so check all that apply. Then weigh the legitimacy of each. If management says to use it, until you own your own company, this is a no-brainer. If it has reached general news, it could be popular, but it could also be overhyped.

How much do you trust each source? What was the specific use case they described?

02

Solves a Problem

Ideas are plentiful because anything can be built in software. The tech will not last if it does not solve an actual problem, and it needs to be profitable or it is not useful. Is this the hammer without the nail?

1What is the problem?
2How do people solve it today, and what does that cost them?
3What breaks if you take the new tech out?
4Are there any other uses for the tech?
5Any downsides or ethical concerns?
03

Get Specific

When you hear about an idea, you might get part of it or the general idea, but not actually how to use it. It’s easy to get overwhelmed. You want to get specific on exactly what you want to learn. Let’s use AI as an example. It’s such a broad and overloaded term. We could be talking about programming productivity tools or building a model to incorporate into your product. Or adding a chatbot for support or using a coding agent to help you write tests. The options can be endless if you’re creative.

For me, I started with one tool, the first AI programming productivity tool my company offered. I started there because I could test it in my general work. That gave me some ideas, and when I started using a second productivity tool, I was able to compare and contrast the two. Now that I know how it feels to be a user of AI, I can start to delve deeper. I can learn ways to integrate it into the tools my team offers. I know our users would prefer to use natural language rather than YAML or JSON. Since I know I would, it’s worth trying it out. I’ll go into other reasons why in further sections.

1Exactly what you want to learn
2How you could use it
3Smallest part of it you can try today
4Steps to the rest of what you want to learn

Look for other versions of the same tool available and compare their features. 05

Use at Work

The best new tech is the one I can try right now. I hear cool ideas all the time that I don’t dig into or forget because time passes without having a specific reason to use them. You might have the time to pursue projects at home, but I have too much TV to watch.

Looking at the variations you listed, check whether one is already available at your company. Anything you already have access to is immediately easier to access. If one of your coworkers is already using it, they can even help you if you get stuck. Especially if it requires a license or a security review, it could take time for that to be approved.

A package that looks straightforward can carry hidden security problems. If the tech you are considering is open source, there are three extra questions in the checklist below.

What has to happen before you can touch it, and how long will that take?

Once you have the new shiny tech in hand, use your checklist to determine if it’s the right one for your problem. This should help you move faster and make the case to management that you need time for research. You’ll need approval if this time wasn’t already allocated during project planning. Consider this worksheet the initial brainstorming for that pitch.

1Can the tech be incorporated into a current product?
2Do you have a new product idea for it?
3What is the ROI if you get the tech?
4What do you lose if you don’t get the tech?
5How long to check your hypothesis?
6How long to integrate the tech?

06

Job Descriptions

This is more big-picture, future-facing. You’ll want to be aware of new tech starting to appear in job descriptions. Especially if it is for jobs above your current level, or at interesting companies you want to work for one day. You should even be watching job descriptions at your own company, since that could affect salary and promotions. You want to make sure you are learning the skills you need to stay employed. It is so easy to keep your head down and just do the work you have always done. It’s boring, but it’s fast, and you don’t have to think about it. If you are reading this, you might be in that rut now and want to get out of it.

Learning and trying new tech is a great way to get yourself out of a boring routine. In engineering, it’s essential to keep up to make more money. When it comes to my example of AI, of course you need to learn how to use it. It doesn’t matter if the investment bubble bursts before this book is published; there are too many use cases for it to be entirely hype. As with any new tech, it can have a steep learning curve, but you don’t want to be left behind. If you haven’t read Chapter 6: Using AI Without It Using You, it can be a jumping-off point for integrating AI.
